**QA-01: PDF zoom does not enlarge the page**

Reproduce on `/reports/home-lab-architectural-study` at 320px wide. Let the PDF load, reset zoom, then press Zoom in twice. The toolbar changes from 100% to 150%, but the canvas stays approximately 246 × 352 displayed CSS pixels. On `/reports/wildfire-analysis-with-pyspark` at 390px, the same sequence leaves it approximately 316 × 409 CSS pixels. The canvas bitmap changes, while its displayed dimensions remain fixed by the responsive size constraint.

This prevents readers from enlarging small PDF text within the embedded viewer. The direct Open PDF link works and supplies a fallback. Allow zoom to enlarge the displayed canvas inside a scrollable container, with a separate fit-to-width action. Keep page navigation and resize behavior intact.

**QA-02: Calculator currency mismatch**

Open `/posts/building-a-private-ai-server-for-friends` and inspect the GPUShare cost calculator. It labels local costs `NZ$` and cloud costs `$`. The deployed calculation divides the USD cloud cost directly by the local electricity cost, without a conversion. With the default settings it compares approximately NZ$0.20/month with US$0.45/month to produce “2x cheaper”.

Select the US preset: the rate becomes $0.168/kWh, but the local outputs still say `NZ$`. EU behaves the same way. The calculation needs an explicit currency definition for each preset, and both sides must use a common currency before producing a comparison. A dated, documented conversion assumption would make the comparison inspectable.

**QA-03: “Cheaper” claim has no equal/more-expensive state**

Select Qwen3 14B, set tokens per response to 4,000, responses per day to 500, and electricity rate to $0.600/kWh. The displayed totals are local NZ$40.54/month and cloud $36.00/month, yet the result says “1x cheaper”. The deployed formatter rounds the raw multiplier, then unconditionally appends `x cheaper`.

Even before fixing currencies, this wording contradicts the calculator's own numeric comparison. Once currencies are normalized, handle below-one, near-one, and above-one ratios separately, and avoid rounding a small advantage into a misleading “1x cheaper” label.

**QA-04: Mobile menu dismissal and label**

At a mobile width, open the navigation menu. Press Escape while its summary is focused: it remains open. Click a point outside the panel, such as the left page gutter: it remains open. The close icon appears while the accessible label still says “Open navigation menu”. Enter and Space toggle the disclosure successfully, and the menu links work.

Support Escape and outside-click dismissal, update the action label while open, and preserve appropriate focus when closing. This is a usability improvement with an accessibility-label defect; it does not prevent navigation.

**Separate local build finding**

**QA-07: High for rebuilding this checkout.** `pnpm run build` passes Astro checking, then fails while prerendering with `Cannot read properties of null (reading 'length')` in `validateWorkStories`. A read-only query of the published Sanity data confirms that The City has `interventions: null` and no supporting-artifact array. The local validator accesses `story.interventions.length` directly at `src/lib/work.ts:104`.

The live site renders The City successfully using a newer implementation. This finding concerns this checkout's compatibility with the current content. Synchronize the local implementation with the deployed content model, or make validation report missing data cleanly and reconcile the required fields. Re-run a full build after that work. This audit did not write to Sanity.

The local environment ran Node v26.7.0; repository CI specifies Node 22. The missing-array data explains the observed failure, but the CI-version build was not rerun in this pass. The first sandboxed build failed to resolve Sanity; the network-enabled retry reached the confirmed validation failure above.

**Coverage limits**

This was a browser and HTTP audit, with local automated checks. It did not cover real-device Safari/iOS, Firefox, screen-reader output, operating-system high-contrast mode, actual browser text zoom, or a simulated reduced-motion preference. Browser screenshots and DOM measurements support the visual findings, but this is not a WCAG conformance certification.

No successful recommendation was submitted to the production store, no booking was made, and no email was sent. Form success/error behavior and private authenticated stats behavior therefore remain unverified end to end. HTTP link checks establish reachability, not the operation of the linked third-party products. LinkedIn's automated-access response does not establish a broken profile.
